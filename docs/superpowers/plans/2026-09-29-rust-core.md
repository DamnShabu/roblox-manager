# Rust Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `rbxmgr-core` Rust library: every behaviour of `roblox-manager.py` except drawing, tested without GTK.

**Architecture:** A Cargo workspace with `crates/core` (the library) and `crates/app` (a stub binary until part 2). Core areas are directories. Each seam into the outside world is a trait with two adapters: production, and the one the tests use.

**Tech Stack:** Rust 1.96 (via Nix), serde/serde_json, ureq 2 (rustls), zbus 5 (blocking), thiserror 2, rand 0.8, chrono 0.4; tempfile (dev).

**Spec:** `docs/superpowers/specs/2026-09-29-rust-core-design.md`

**Execution note:** the implementer is the same session that wrote the spec. Each task lists files, interfaces and its exact test cases, and code is written test-first during execution. The Python app (`git show HEAD:roblox-manager.py`, current tree `roblox-manager.py`) is the reference for every formula, URL and message. Port from it; don't reinvent.

## Global Constraints

- No `.rs` file over 600 lines. Enforced by `crates/core/tests/size_limit.rs`.
- `rbxmgr-core` has no GTK/GLib/UI dependency.
- No `unwrap`/`expect` outside tests. No swallowed errors except `Keyring::forget`.
- `cargo test`, `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` all pass after every task.
- File formats, paths and keyring attributes are unchanged from the Python app (spec, "Compatibility").
- `Cookie` never prints its value.
- Commands run in the dev shell: `nix develop -c cargo …`.

## Review Focus

1. **A JSON file edited by hand, or written by an older version** (missing fields, wrong types, unknown keys): the file loads with defaults and saves without losing unknown keys. *Test in Task 9:* an account with an unknown key plus `"selected": "yes"` loads, and saves back with the unknown key present.
2. **A keyring that is locked and whose prompt is dismissed:** every operation except `forget` returns an error naming the reason. *Test in Task 3.*
3. **Roblox answering with HTML or an empty body instead of JSON** (outage pages): an error with the HTTP status, not a panic. *Test in Task 4:* a 503 with an HTML body → `RobloxError::Http { status: 503, .. }`.
4. **A label, or a macro name, containing spaces or non-ASCII characters:** it round-trips through the keyring attributes and macros.json unchanged. *Tests in Tasks 3 and 10.*
5. **A client that exits during the 5 s startup check with an empty log:** the error still names the exit status and the log path. *Test in Task 7.*

### Task 2: Shared types, paths, JSON files

**Files:** `crates/core/src/{types.rs, paths.rs, json_file.rs}`

**Produces:**
- `Label::parse(&str) -> Result<Label, InvalidLabel>`, `Label::as_str`
- `UserId(u64)`
- `PlaceId::parse(&str)`, digits only
- `ServerId::parse(&str)`, alphanumeric and `-`
- `Profile::of(UserId)` → `rbxmgr-<id>`, `Profile::as_str`
- `Cookie::new(String)`, `Cookie::expose(&self) -> &str`, with `Debug` printing `Cookie(***)`
- `User { id: UserId, name: String, display_name: Option<String> }` (serde, `displayName`)
- `Paths { state, cache, data, config, runtime }` via `Paths::from_env()` and `Paths::under(root)` for tests, with methods `accounts()`, `groups()`, `macros()`, `icons()`, `logs()`, `cordial_profiles()`, `cordial_shell_json()`, `flatpak_cordial()`, `runtime_dir()`
- `json_file::read<T: DeserializeOwned + Default>(path) -> T` (a missing or corrupt file gives `T::default()`, as Python does)
- `json_file::read_opt` (None when missing)
- `json_file::write(path, &T) -> io::Result<()>` (create parents, write `.tmp`, rename)

**Tests:**
- Labels: empty, `a/b`, `.`, `..`, `_icons` and `alt\n1` are rejected; `alt 1` and `ñame ✓` are accepted.
- `PlaceId::parse("1818&x=1")` and `ServerId::parse("abc&accessCode=x")` are errors.
- A cookie's `{:?}` does not contain the value.
- XDG resolution: an unset *or empty* `XDG_DATA_HOME` falls back to `~/.local/share`; an unset `XDG_RUNTIME_DIR` falls back to `/run/user/<uid>`. Test through a `from_vars(|k| …)` constructor, never the process environment.
- `json_file`: round trip; a missing file gives the default; `{not json` gives the default; a write leaves no `.tmp` behind.
- [ ] Commit `feat(core): shared types, paths, atomic JSON files`.

### Task 3: Keyring

**Files:** `crates/core/src/keyring/{mod.rs, dbus.rs, memory.rs}`

**Consumes:** `Label`, `Cookie`.

**Produces:**
- `type Attrs = BTreeMap<String, String>`
- `trait Secrets`, as in the spec
- `Keyring::new(Box<dyn Secrets>)` with `cookie`, `set_cookie`, `drop_cookie`, `move_cookie`, `put`, `delete`, `forget`
- `KeyringError { Locked(String), NoCookie(Label), Dbus(String) }`
- `MemorySecrets::default()` / `MemorySecrets::locked(reason)`, with `unlock_count()` and `items()`
- `DbusSecrets::connect() -> Result<Self, KeyringError>`, which ports the Python D-Bus calls:
  - `ReadAlias("default")`, the `Locked` property, `Unlock`, the `Prompt` + `Completed` signal;
  - `OpenSession("plain")`, `SearchItems`, `GetSecrets`, `CreateItem(replace=true)`, `Item.Delete`;
  - a 180 s prompt timeout, waited on the calling thread with a blocking signal iterator.

**Tests** (through `Keyring` over `MemorySecrets`):
- `set_cookie` then `cookie` round-trips, stripping surrounding whitespace.
- The attributes are exactly `{app: rbxmgr, account: <label>}`, and the item label is `rbxmgr <label>`.
- `cookie`, `set_cookie`, `drop_cookie`, `put` and `delete` each call `unlock` once.
- A missing cookie gives `NoCookie`, whose message contains "Sign in again".
- With a locked adapter whose unlock is refused, every method except `forget` errors with the reason; `forget` returns and does not unlock.
- `move_cookie` leaves only the new label.
- A label with spaces and non-ASCII characters round-trips.
- `DbusSecrets` has no unit test (it needs a session bus). It is kept thin and exercised by the part 2 smoke run.
- [ ] Commit `feat(core): keyring with Secret Service and in-memory adapters`.

### Task 4: Roblox HTTP and account APIs

**Files:** `crates/core/src/roblox/{mod.rs, http.rs, users.rs, presence.rs, friends.rs}`

**Produces:**
- `trait Transport: Send + Sync { fn send(&self, req: Request) -> Result<Response, RobloxError>; }`
  - `Request { method, url, cookie: Option<Cookie>, csrf: Option<String>, referer: bool, json: Option<Value> }`
  - `Response { status: u16, headers: Vec<(String, String)>, body: Vec<u8> }`
  - Adapters: `UreqTransport` (User-Agent `UA` from Python, 20 s timeout, HTTP errors returned as a `Response` rather than an Err) and `tests::Canned` (a queue of responses that records requests).
- `HttpRoblox::new(Arc<dyn Transport>)` implements `Roblox`.
- `http::post_csrf(t, req)`: on 403 with `x-csrf-token`, retry once with it.
- `http::detail(&Response) -> String`: `HTTP <code>`, plus the 2FA sentence when a `rblx-challenge-type` or `rbx-challenge-id` header is present, plus up to 400 bytes of body.
- `RobloxError { Expired, Http { status, detail }, Offline(String), BadResponse(String) }`
- `whoami` (401 → `Expired`)
- `presence(cookie, &[UserId])`, batched in 50s
- `leader_presence -> (Option<ServerId>, Option<PlaceId>)`
- `friends -> Vec<Friend { id, name, display, state: FriendState { Game, Online, Offline }, place, server, game }>`, with the ranking and name lookup batched in 100s, as in Python

**Tests** (with `Canned`):
- A POST that gets a 403 with a token is retried with `X-CSRF-TOKEN`; a 403 without a token is not.
- 401 on whoami gives `Expired`.
- A 503 with an HTML body gives `Http{503}` with the body in `detail`.
- The challenge header adds the 2FA sentence.
- 120 user ids make 3 presence requests.
- Friends are sorted game → online → offline, then by display name case-insensitively; a Studio user (type 3) counts as online; a missing name gives `user <id>`.
- [ ] Commit `feat(core): Roblox web API — transport, users, presence, friends`.

### Task 8: Launcher

**Files:** `crates/core/src/launch/{mod.rs, each.rs, group.rs}`

**Consumes:** the `Roblox` trait, `Keyring`, `CordialProfiles`, `roblox_build`, `join_url`.

**Produces:**
- `Pacing { stagger: Duration, leader_timeout: Duration, poll: Duration, sleep: Arc<dyn Fn(Duration) + Send + Sync> }`, with `Pacing::default()` = 8 s, 90 s, 3 s and `thread::sleep`

- `LaunchRequest`, `LaunchReport`, as in the spec
- `LaunchError::Build(CordialError)`
- `Launcher::new(...)`, with a `build` function injected so tests skip cordial-fetch

**Tests** (with a fake `Roblox` and the Task 7 fakes):
- Each mode: every account launches; an account already running is skipped with no stagger; the stagger happens only between real sign-ins.
- Group mode:
  - the leader first; followers join `join_url(leader place, server)`;
  - the leader already running → the server is looked up immediately;
  - no server within the timeout → followers get their own servers;
  - the leader fails → nobody else launches;
  - with no followers, presence is never polled.
- An expired session is in `expired`; any other failure is in `failed` with its message.
- A build failure gives `Err(LaunchError::Build)`.
- [ ] Commit `feat(core): launcher for each and group launches`.
